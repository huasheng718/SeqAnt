# Codeup 平台集成 PRD

2026-11-23；基线 `2e37094`；Trellis 任务 `11-23-codeup-platform-integration`；状态：首期 Git-only / 个人 PAT 已实施；OpenAPI / MR 仍单独规划。

## 目标

在“项目配置 → 添加凭证 → 平台集成”增加阿里云云效 Codeup。用户可以在熟悉的凭证列表管理自己的 Codeup 认证信息，并使其用于目标 Codeup 仓库，而不是只新增一个不可用图标。

当前入口位于项目设置中，但现有 GitHub / Gitee / GitLab 凭证由用户拥有；新增 Codeup 沿用这一所有权，不变成项目共享密钥。

## 已确认事实

- 当前产品已有 Gitee / GitLab 的个人凭证、HTTPS 克隆推送及按主机分配认证链路；尚无 Codeup 实现。
- 官方说明个人访问令牌可用于云效 API 和 HTTP Git；另有单独的 HTTPS 克隆账号 / 密码设置。二者不能在界面中混称，也不能直接替用 GitHub 或 GitLab 凭证。
- 用户提供的是产品概述，不能据其推导全部 OpenAPI 鉴权字段或声明合并请求已支持。[来源与边界](research.md)。

## 需求

| CU05 | HTTPS 克隆 / 拉取 / 工作分支推送在既有本机与 Runner 路径按当前责任人的 Codeup 凭证执行；只匹配受支持的 Codeup 主机 |

## 集成深度

本轮按推荐首期实施：

1. **已实施首期**：对齐 Gitee/GitLab，完成个人凭证管理、Codeup 仓库接入所需的 HTTPS Git 主机凭证链路；云效 OpenAPI 和 MR 另期。
2. 同时接入云效 OpenAPI 与合并请求交付：需要补充组织 ID / 仓库 ID 映射、鉴权方式、幂等 MR、交付适配与真实权限验收。

CU04–CU07 按首期范围落实；若后续选择完整 OpenAPI，还需新增可观察的 MR 验收标准，不能把它当作已有 GitLab API 的别名。

## 交互草图

```text
添加凭证 / 平台集成
  GitHub   Gitee   GitLab   Codeup   Git SSH
                           ↓
  Codeup（云效代码管理）
  用于本人 Codeup 仓库的 HTTPS 访问
  官方设置说明 ↗
  认证方式 / 克隆账号 / 密码或令牌（按核对后的方式填写）
  [取消]                         [保存]
                           ↓
  Codeup   已配置 · 尚未验证目标仓库   [修改] [移除]
```

复用现有向导，不新增一整套凭证页面。官方品牌素材必须核对许可与来源；没有可用素材时先用标准图标与文字，不擅自生成伪官方 Logo。

## 验收边界

本地字段 / 权限 / 凭据分发和 Git 行为测试与真实 Codeup 验收分开记录。未提供真实 Codeup 账号或测试仓库时，真实克隆 / 推送 / API / MR 均保持未验证，不能将本机 Git 模拟当成云效认证通过。

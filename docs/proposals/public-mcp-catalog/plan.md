## 1. 建议结论

把「能力资产 → MCP → 浏览公共 MCP」从 GitHub 外链改成站内的**公共 MCP 选择器**。用户完成「浏览模板 → 查看详情 → 填写配置、按需测试 → 添加到指定范围 → 选择角色使用」，整个主流程不离开 SeqAnt。

推荐首期采用**平台维护的精选公共配置模板**，先做完整的选择和配置闭环。首批候选为 GitHub、Context7、Filesystem、Fetch、Playwright；除已存在的 GitHub 目录项外，其余均为**拟新增候选**，需在实施时核对官方文档、固定依赖版本并完成环境验收，才进入正式可配置目录。原型中的五项和所有测试结果都是演示数据。

官方 MCP Registry 可作为后续的「发现更多」来源。第一期不把联网抓取 GitHub README 或全量第三方 Registry 作为页面正常使用的前提，不把「目录收录」等同于「适配完成、可一键运行」。

### 公开来源核查

- 用户当前跳转的 [MCP servers 仓库](https://github.com/modelcontextprotocol/servers) 是参考实现与链接资料，不是 SeqAnt 可直接执行的配置目录。
- 已读取官方 [Registry 列表 API](https://registry.modelcontextprotocol.io/v0.1/servers?limit=3)：响应为 `servers` 与 `metadata`，支持游标；样本出现同一服务的不同版本，并包含 `remotes` 等运行描述。直接把每条结果画成「安装」卡片，会产生版本重复和缺少实际配置 / 认证适配的问题。
- 后续若接入 Registry，需先处理名称与版本去重、HTTP / stdio 适配、输入参数和认证映射、失效项与缓存；只展示元数据时应标记「需自定义配置」。

## 4. 信息架构与线框对应

```text
能力资产 / MCP（现有页面）
  ├─ 范围：本项目 / 个人
  ├─ 已添加列表：配置、连接状态、角色使用情况
  ├─ 添加 MCP：保留原自定义入口
  └─ 浏览公共 MCP：打开站内选择器
       A. 目录：搜索 / 分类 / 传输方式 / 来源 / 同范围已添加状态
       B. 详情：用途 / 来源 / 接入方式 / 配置要求 / 环境依赖
       C. 配置：安装范围 / 名称 / 字段 / 执行环境 / 显式测试
       D. 结果：配置已添加 / 连接检查结果 / 下一步绑定角色
```

### A. 浏览目录

- 保留外层页面，使用一个宽弹窗承载目录与后续配置。桌面最大约 1120px；列表独立滚动，底部操作固定。窄屏为接近全屏的单列面板，所有按钮留在视口内。
- 左侧分类、上方搜索和传输方式筛选，右侧模板列表。每项显示名称、简短用途、HTTP / stdio、认证 / 环境要求、来源以及同一范围是否已添加。
- 默认继承外层的项目 / 个人范围。切换范围即更新重复项判断；其他项目已添加不影响当前项目。
- 在详情内才保留「查看官方来源」外链，不再把它当成主按钮。
- 「平台维护」只表示配置模板由平台整理，不能替代远端连接验证；不伪造安装量、评分、工具数量或官方认证。

### B. 查看详情

- 展示能完成什么任务、会访问什么资源、认证方式、依赖条件和模板来源。
- HTTP 显示服务地址与认证要求；stdio 显示运行环境、命令预览和用户要填写的参数。
- 未检查前工具列表显示「连接后读取」，不根据产品名称编造 tools/list 结果。
- 已添加的模板进入「查看当前配置」；未添加的模板进入「配置此 MCP」。同一选择器内切换视图，返回时保留搜索与填写内容。

### C. 配置与显式检查

- 安装范围：项目 / 个人。项目范围显示具体项目；个人范围绑定当前登录人，不能替别人安装。未选项目时允许转个人范围，或返回先选项目。
- 基础字段：名称、接入方式、模板声明的参数、执行环境与超时。普通用户先看业务字段，高级区再展示最终配置预览。
- GitHub 复用已有 `github-token` 认证模式；不把 GitHub/Gitee/GitLab 的令牌互相替用。其他模板如需密钥，仅使用已声明的 header/env 字段，沿用现有脱敏与修改保留逻辑。
- GitHub 的检查使用当前操作者的凭证；任务运行仍按现有规则使用任务责任人凭证。界面不得把「当前账号已配置」当作所有责任人都已获得权限。
- HTTP 首期检查从平台发起，结果明确显示「测试位置：SeqAnt 平台」；这不能替代执行机器的网络可达性验收。
- stdio 检查由用户明确发起，并在指定、受支持的隔离执行环境中启动进程；禁止在 API 宿主机直接运行目录安装脚本。暂不可提供对应环境时，显示「当前环境不可测试」，允许仅保存，不能伪造通过。
- 检查只执行协议握手与 `tools/list`，不调用业务工具，不以测试名义创建 Issue、修改文件或写外部系统。
- 修改 URL、密钥、启动参数、模板版本或测试环境后，前一次结果失效，回到「未测试」。检查通过只绑定当前配置摘要和测试位置；服务在未来仍可能失效。
- 配置完整时可选择「添加配置」。检查失败 / 未检查也可保存，结果标为「未通过 / 未测试」；缺必填项则不能保存。个人没有项目写权限时，项目保存不可用，但不阻止浏览目录或保存自己的个人配置。

### D. 添加结果与角色使用

- 添加成功显示配置名称、安装范围、连接检查状态；返回外层列表时定位新增项。
- 提供「去绑定角色」与「返回已添加列表」。不默认把新 MCP 绑定到全部角色，也不改变已有角色的能力集合。
- 首期复用角色定义页的绑定能力，只导航并定位相关项目 / MCP。原型的角色勾选用于说明下一步，不代表另建一套角色编辑 API。
- 项目 MCP 只提供该项目可选角色；个人 MCP 只进入当前用户可使用的选择范围，禁止写入其他人的个人资产或共享角色。
- 受控任务不启用外部 MCP 的策略保持不变。结果页可提示「已添加配置；实际调用仍受任务策略限制」，不能显示「所有任务已启用」。

## 5. 模板示例（不是当前已上线目录）

| 候选模板 | 接入方式 | 用户主要填写 | 实施前需要核验 |
| --- | --- | --- | --- |
| GitHub | HTTP | 使用任务责任人 GitHub 凭证、可选超时 | 现有认证边界与个人范围安装 |
| Context7 | HTTP | 官方地址、可选 API Key | 官方 header 规则、匿名使用限制、实际工具发现 |
| Filesystem | stdio | 沙箱工作区内允许访问的目录 | 固定包版本、路径约束、实际读写能力；不能把宿主机任意目录暴露进去 |
| Fetch | stdio | 超时等少量选项 | Python / uvx 等运行依赖、实际启动与工具发现 |
| Playwright | stdio | 浏览器运行方式、必要参数 | 固定包版本、浏览器依赖和隔离环境兼容性 |

正式模板中的包和脚本固定版本；不默认执行 `latest` 或用户未确认的远端脚本。高级区修改超出模板声明范围时，应另存为自定义配置，不伪称仍是原模板的受支持实例。

## 6. 状态与异常设计

| 状态 | 显示与处理 |
| --- | --- |
| 目录加载中 | 固定骨架；不显示“0 项”冒充加载完成 |
| 未搜到 | 展示当前关键词 / 筛选条件，提供清空筛选和添加自定义 MCP |
| 目录获取失败 | 显示重试；本地已添加配置仍可查看与管理 |
| 缺少必填配置 | 字段旁标明原因，提交时聚焦首个错误字段 |
| 当前账号缺少 GitHub 凭证 | 提供跳到个人凭证的入口；返回后保留配置草稿 |
| 无法鉴权 / 超时 / 执行环境缺依赖 | 分别给出原因和可操作建议；保留已填内容；不更新成“已连接” |
| 同范围已添加 | 跳到现有配置；并发提交仍以服务端唯一性 / 冲突响应为准 |
| 中途切换项目 / 用户 | 取消旧的安装提交与检查请求，不把结果写到新的范围 |
| 项目或个人范围无权写入 | 403 展示实际限制，不能只靠隐藏按钮控制权限 |
| 用户取消检查 / 关闭面板 | 停止对应请求，清理临时进程与资源；迟到结果不能覆盖新的配置 |
| 模板更新 | 已安装实例保留自身配置和模板版本，不自动覆盖 |

## 7. 落地设计

### 7.1 数据模型与接口

沿用原有目录与安装接口，不增加新的市场服务、注册中心或运行时层。

1. 扩展内置目录项，补充 `templateVersion`、来源信息、`configuration` 默认配置、`fields` 声明式输入定义和 `requirements` 环境要求。
2. `GET /api/mcp-market` 保持已有响应兼容，增加分类与传输方式筛选元数据。首期数据量小，使用现有快照和确定性筛选即可。
3. `POST /api/mcp-market/install` 支持项目 / 个人及受限字段覆盖；服务端根据模板生成配置并验证作用域、必填项、路径和 URL，不能直接信任前端生成的整个命令对象。
4. 拟新增 `POST /api/mcp-market/check`：带目录项、模板版本、参数、作用域、测试位置；返回 `passed / failed / unavailable` 终态、脱敏原因和测试位置，`untested / checking` 由界面维护。不持久化为 MCP 安装记录，不存储测试提交里的密钥副本。
5. 安装实例继续使用 `MCPServerDefinition`，保留 `MarketID` 与已有 GitHub 别名；只补充必要的模板版本 / 来源 / 检查凭证元数据。若检查结果要持久化，必须与配置摘要、环境绑定，不以单个永久绿色布尔值代替。
6. 不新增通用凭证库。Headers / env 通过既有持久化与脱敏逻辑保存；日志、错误、列表、导出预览都不得返回密钥明文。
7. `CatalogRepo` 承接目录资产持久化，`UsersRepo` 承接现有个人凭证，`marketHandlers` 承接选择器接口；保持 `Store` 只做装配。所有数据迁移与 seed 仍需手动 SQL，不做启动数据补写。

### 7.3 验收清单

- 原来的按钮打开站内选择器；只有显式「查看来源」会打开外站。
- 能用搜索、分类和接入方式找到条目，并在详情看到配置要求。
- 项目 / 个人范围可正确添加，新增记录能在当前列表看见；不出现跨项目重复判断错误。
- HTTP 与至少一项经验证的 stdio 模板，能生成可用配置并在声明的环境完成真实握手和工具列表读取。
- 未测试、失败、已添加、已绑定、受策略限制彼此独立，不以“添加成功”冒充“可运行”。
- 测试不调用业务工具，缺依赖 / 凭证无效 / 超时能处理，取消能释放资源。
- 已存密钥不以明文回填 HTML / DOM；新输入仅保留于临时表单状态，提交后清理，不进入查询串、日志或公共导出；编辑掩码不会抹掉已保存密钥。
- 目录安装继承现有项目写权限和个人所有权；服务端校验不能由前端绕开。
- 重复安装、并发冲突、项目切换、刷新恢复、角色绑定与受控策略均有明确处理。
- 桌面 / 手机、明暗主题、键盘、减少动态效果与模态焦点检查通过。

## 8. 原型说明与确认点

- 原型只用于评审布局和交互；不会发请求、安装程序、写入真实项目或保存真实凭证。
- 原型可点选服务、查看详情、切换项目 / 个人、填写示例参数、模拟检查成功与失败、添加后查看下一步；关闭 / 返回保留本次会话草稿。
- 线框阶段使用黑白灰强调层级；实施采用 `design.md` 的 SeqAnt 矿物青与 Harness 组件，不重新设计全站壳层。

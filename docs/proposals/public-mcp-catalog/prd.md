# 公共 MCP 可视化选择与配置 PRD

- 版本：v1.0，2026-11-23。
- 状态：完整方案待实施确认；线框方向已获认可。
- 来源：用户要求把“浏览公共 MCP”外链改成可视化配置选择，已确认[四步线框](wireframe-overview.png)。
- 技术基线及代码证据见 [research.md](research.md)，接口与实现细节分别见 [design.md](design.md)、[implement.md](implement.md)。

## 1. 目标与用户价值

用户在 SeqAnt 内找到适合自己的公共 MCP，了解认证和运行条件，通过表单生成正确配置，按项目或个人保存，并明确下一步如何供角色使用。普通接入不要求阅读 GitHub README 或手写 JSON。

成功标准：主流程不离开平台；用户能区分“目录模板”“已添加配置”“本次连接检查通过”“角色已绑定”和“当前任务允许调用”。

## 2. 用户与权限

| 身份 | 浏览公共目录 | 项目配置 / 项目检查 | 个人配置 / 个人检查 |
| --- | --- | --- | --- |
| 已登录项目可写成员 | 可以 | 当前有写权限项目 | 仅自己 |
| 已登录项目只读成员 | 可以 | 不可；说明权限原因 | 仅自己 |
| 已登录但未选项目 | 可以 | 提示先选择有权限项目 | 仅自己 |
| 匿名 / 访客 | 随平台现有页面访问策略 | 不因新增入口获得写入或检查权限 | 提示登录 |

项目权限沿用现有 owner/admin/non-viewer 判定及既有兼容规则。平台管理员不因此获得操作他人个人 MCP 的新入口。服务端校验用户、范围和目标，不能只通过前端隐藏按钮限制。

## 3. 首期范围

包含：精选目录、搜索筛选、详情、模板表单、项目与个人范围、添加与修改、显式连接检查、结果反馈、列表定位、已有角色页衔接，以及现有自定义 / JSON 导入功能的兼容。

候选：GitHub、Context7、Filesystem、Fetch、Playwright。只有核对来源、许可、固定版本、参数及支持环境并通过适配的条目才作为可配置模板发布；未完成条目显示候选或不发布。

不包含：全量 Registry 同步、评分评论、多源市场服务、自动依赖升级、通用 OAuth / 凭证中心、新 Worker 调度协议、自动角色授权、放宽受控交付策略、持续健康监测。

## 4. 需求

### R01 站内入口与目录

原“浏览公共 MCP”打开站内宽面板，保留当前设置页面和自定义添加入口。桌面目录按分类与卡片展示，手机使用可滚动单列面板、固定操作区。

支持名称 / 用途 / 发布者搜索、用途分类、HTTP / stdio 筛选，条件组合生效。每项展示名称、用途、接入方式、认证或环境要求、来源以及当前范围是否已添加；不展示虚构热度、评分或工具数。分类含义与空结果说明清楚。

### R02 范围与重复项

继承外层项目 / 个人范围，展示具体项目或当前账号。已添加状态按模板规范 ID / 别名与目标范围判断。其他项目、其他个人的记录不影响当前可添加状态，不泄露其存在。

同范围一个模板只保留一个目录安装实例。点击已添加条目定位现有配置；并发添加返回“已存在”，不能覆盖第一次保存的参数或密钥。

### R03 详情

显示用途、会访问的资源、认证方式、环境要求和官方来源。stdio 明示将在执行环境启动程序。工具列表仅由真实检查返回；未读取时显示“连接后读取”，没有工具时明确显示 0 项。

### R04 模板配置

用模板字段生成名称、地址、密钥、允许目录、运行方式和超时等必要输入，显示必填项、默认值和帮助。高级区可查看脱敏后的最终配置；超出模板声明范围的改动走自定义配置。

必填和路径错误在对应字段显示，提交聚焦首个错误。向前 / 返回保留当前草稿；切换服务或范围时不把旧密钥带入其他配置。密钥不进入 URL、日志、公共预览或持久浏览器存储。

### R05 添加、修改与兼容

配置完整即可添加，未检查或检查失败也可保存，但结果必须如实标示。已添加目录配置可修改模板声明的参数，保留原安装 ID、作用域和角色引用；不要求删除重装才能换 Key。

保持既有 GitHub ID / 别名、固定配置的旧安装请求、自定义配置和 JSON 导入可用。目录变更不自动覆盖已有实例；未知旧模板仍能查看、移除或另存自定义，不静默升级。旧记录缺少来源版本时显示“历史配置”，不制造通过记录。

### R06 显式 HTTP 检查

用户主动点击“测试连接”，界面显示测试位置、进行中、完成时间及结果。仅执行协议初始化和工具目录读取，不调用业务工具。握手失败即失败，不因为能连上地址或有 HTTP 200 就显示通过。

GitHub 检查使用当前操作者凭证；任务执行仍按既有责任人凭证规则。缺少凭证时提供个人凭证设置入口，并说明当前检查不能证明其他责任人有权限。

### R07 显式 stdio 检查

用户主动启动独立隔离环境内的检查，清楚显示将启动程序及环境要求。首期支持平台 Docker 检查；不在 API 宿主机直接执行模板命令，不读取真实项目目录。演示工作区只包含合成文件。

没有可用隔离环境或预备依赖时显示“当前环境不可测试 / 缺依赖”，仍可保存合法配置。检查完成、取消、超时、页面关闭或请求断开后应回收进程、容器和临时文件，不影响其他任务。

### R08 检查状态与有效期

状态为未测试、检查中、通过、失败、环境不可用。URL、密钥、参数、模板版本、范围或测试位置变化后，前次结果失效。已返回的旧请求不得更新新草稿。

首期仅显示当前页面会话内的本次检查结果。添加后可延续同一草稿的结果供用户查看；刷新 / 重新登录后显示“未测试（本次结果未保留）”，不写永久健康状态，不把检查当作授权凭证。

### R09 添加结果与角色衔接

结果显示名称、范围、保存状态、连接检查状态和角色绑定状态。可继续浏览、回列表定位，或导航现有角色定义页按需绑定。

新配置不默认绑定角色。个人 MCP 只进入当前用户有权使用的角色 / 任务选择范围；不能借此修改共享角色或他人资产。受控任务禁止外部 MCP 的策略保持有效。

### R10 异常与访问体验

明确处理加载、目录失败、空结果、401、403、重复、参数错误、凭证无效、协议不兼容、超时和缺依赖。能重试时保留非敏感填写内容；错误不包含凭证或远端原始响应。

沿用 SeqAnt / Harness 明暗主题、图标及控件；支持手机、键盘、Escape、焦点返回、减少动态效果。模态打开后背景不可操作，操作区不溢出视口。

## 5. 验收条件

| 编号 | 通过条件 | 需求 |
| --- | --- | --- |
| AC01 | 主按钮打开站内目录；仅来源链接打开外站；自定义入口仍可用 | R01 |
| AC02 | 搜索 / 分类 / 传输组合和清空条件正确，失败 / 空态不同 | R01 |
| AC03 | 两个项目与两个人的已添加状态互不污染 | R02 |
| AC04 | 并发添加同范围模板只有一个创建成功，后者不能覆盖参数 | R02 |
| AC05 | 详情显示来源与依赖；未检查不显示编造工具 | R03 |
| AC06 | 必填、名称、目录、超时校验有效；返回保留草稿；切换不串密钥 | R04 |
| AC07 | 添加个人目录 MCP 后本人可见、可改、可删，他人不可访问 | R05 |
| AC08 | 修改目录参数保留安装 ID / 范围 / 角色引用，未改密钥正确保留 | R05 |
| AC09 | 旧 GitHub 请求 / ID / 别名及自定义 / 导入路径回归通过 | R05 |
| AC10 | 实际 HTTP 初始化与工具列表读取成功；初始化失败绝不能通过 | R06 |
| AC11 | 实际 stdio 在声明隔离环境握手成功；API 主机无模板进程 | R07 |
| AC12 | 无依赖 / 无 Docker / 无权限有明确状态，可保存而不虚报通过 | R07 |
| AC13 | 取消 / 断开 / 超时后检查资源回收；无跨检查资源误删 | R07 |
| AC14 | 改密钥 / 参数 / 环境及切范围使旧结果失效，迟到结果被丢弃 | R08 |
| AC15 | 刷新恢复已添加配置但不伪造历史通过；本次状态说明清楚 | R08 |
| AC16 | 添加成功可定位和去角色页，实际角色关联经用户确认后才改变 | R09 |
| AC17 | 受控任务仍拒绝外部 MCP；已检查或已绑定不绕过策略 | R09 |
| AC18 | 明暗主题、390px 手机、键盘和焦点验收有截图 / 记录 | R10 |
| AC19 | 列表、详情、错误、预览、日志和导出均不暴露已存密钥 | R04、R10 |
| AC20 | 至少一个实际 HTTP 和一个实际 stdio 模板完成来源 / 版本 / 环境验收 | R03、R06、R07 |

测试用例及证据要求见 [acceptance.md](acceptance.md)。阻塞产品决策已收敛；候选版本和 Docker 支持性属于 MCP-01 / MCP-05 实施前置验证，不能用原型代替。
